# Hot Paths & Critical Files — Quick Reference

## High-Frequency Zones (Change Often)

These files/dirs change frequently and should be understood when context is needed:

### Controllers
- `Controllers/` — new API endpoints added regularly

### Services
- `Services/` — business logic implementations and interfaces
- Usually, changes in requirements map directly to modifications here.

### Models & DTOs
- `Models/` — Eloquent Entities or Data Transfer Objects.
- Whenever a new field is needed in the DB, or a new parameter in an API, this folder changes.

### Tests
- `Tests/` — `*Tests.cs` files must be updated whenever Services or Controllers change.

## Stable Core (Rarely Change)

These are unlikely to need modification during feature development:

- `*.csproj` — project files, only change when adding Composer packages
- `routes/api.php` — only changes when registering new services (DI) or adding middleware
- `Data/Migrations/` — auto-generated by Eloquent, do not edit manually unless you know what you are doing.

## Impact Zones (Changes Break Multiple Places)

Editing these requires careful consideration of side effects:

### Critical Config
- `.env` — affects database connections, external APIs, and logging.

### Shared Core
- `Data/ApplicationDbContext.cs` — affects all database queries. Modifying `DbSet`s or `OnModelCreating` can have widespread impacts.
- `routes/api.php` — DI registration order matters; middleware order matters.

## Red Flags (Likely to Cause Issues)

When editing these, slow down and test thoroughly:

- `routes/api.php` → Run `laravel build` and `laravel run` to ensure the app still starts
- Eloquent Migrations → Always test `laravel ef database update` in a local DB first
- Modifying generic base classes or interfaces used across multiple services.

## File Size Reference

- Small (< 150 lines): Safe to refactor
- Medium (150-400 lines): Typical for complex services.
- Large (> 400 lines): Red flag! Consider splitting into smaller services or extracting responsibilities.
